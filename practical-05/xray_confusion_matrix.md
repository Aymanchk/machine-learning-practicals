Вариант 13, основной уровень. По условию положительный класс («да») означает, что на снимке есть пневмония. В этом задании используются готовые числа из таблицы, а не датасет Titanic из notebook ПР-5.

## 1. Исходная матрица

Строки показывают фактический результат, столбцы - прогноз модели.

| Факт / прогноз | Пневмония | Нет пневмонии |
| --- | ---: | ---: |
| Пневмония | TP = 58 | FN = 8 |
| Нет пневмонии | FP = 9 | TN = 225 |

Всего снимков: 58 + 8 + 9 + 225 = **300**.

## 2. Что означают ячейки

- **TP = 58:** на снимке есть пневмония, и модель ответила «да».
- **FN = 8:** на снимке есть пневмония, но модель ответила «нет».
- **FP = 9:** пневмонии нет, но модель ответила «да».
- **TN = 225:** пневмонии нет, и модель ответила «нет».

## 3. Метрики исходной модели

Округляю до трёх знаков, как указано в задании.

- Accuracy = (TP + TN) / N = (58 + 225) / 300 = 283 / 300 = **0,943**.
- Precision = TP / (TP + FP) = 58 / (58 + 9) = 58 / 67 = **0,866**.
- Recall = TP / (TP + FN) = 58 / (58 + 8) = 58 / 66 = **0,879**.
- Specificity = TN / (TN + FP) = 225 / (225 + 9) = 225 / 234 = **0,962**.
- F1 = 2TP / (2TP + FP + FN) = 2 × 58 / (2 × 58 + 9 + 8) = 116 / 133 = **0,872**.

## 4. Сравнение с моделью, которая всегда отвечает «нет»

Такая модель правильно ответит только на снимках без пневмонии: TN + FP = 225 + 9 = 234. Её accuracy = 234 / 300 = **0,780**. У исходной модели accuracy выше: 0,943 против 0,780.

Но одной accuracy здесь доверять нельзя. Модель «всегда нет» набрала бы 0,780, хотя пропустила бы все 66 снимков с пневмонией. Поэтому нужно также смотреть recall и число FN.

## 5. Какая ошибка дороже

Для этого сценария считаю FN дороже: на снимке есть пневмония, а модель её не отметила. FP тоже нежелательна, поскольку приводит к лишней проверке снимка, но для первичного отбора важнее не пропускать положительные случаи. Поэтому в первую очередь нужно повышать **recall**, продолжая следить за числом FP.

## 6. После снижения порога

По условию 6 случаев перешли из FN в TP, а 28 - из TN в FP. Числовое значение нового порога не дано, поэтому его нельзя вычислить из этой таблицы.

- TP = 58 + 6 = **64**.
- FN = 8 - 6 = **2**.
- FP = 9 + 28 = **37**.
- TN = 225 - 28 = **197**.

| Факт / прогноз | Пневмония | Нет пневмонии |
| --- | ---: | ---: |
| Пневмония | TP = 64 | FN = 2 |
| Нет пневмонии | FP = 37 | TN = 197 |

Проверка: 64 + 2 + 37 + 197 = **300**.

- Precision = TP / (TP + FP) = 64 / (64 + 37) = 64 / 101 = **0,634**.
- Recall = TP / (TP + FN) = 64 / (64 + 2) = 64 / 66 = **0,970**.
- F1 = 2TP / (2TP + FP + FN) = 2 × 64 / (2 × 64 + 37 + 2) = 128 / 167 = **0,766**.

После снижения порога FN стало 2 вместо 8, а recall выросла с 0,879 до 0,970. Для первичного отбора это лучше, если важнее не пропустить снимок с пневмонией. При этом FP стало 37 вместо 9, precision упала с 0,866 до 0,634, а F1 - с 0,872 до 0,766. Значит, улучшение есть именно по выбранному приоритету, а не по всем метрикам сразу.
