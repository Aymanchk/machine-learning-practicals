Подбираю гиперпараметры XGBoost для задачи оттока абонентов внутри честной схемы валидации. Данные `o_churn_synthetic.csv` из ПР-8: 3000 абонентов, целевой столбец `churn` (1 = абонент ушёл). **Датасет синтетический, это не данные реального оператора.**

Какая выборка для чего:

- **test** (20%, 600 абонентов) отложен сразу и используется только один раз, для итоговой оценки;
- **train** (80%, 2400 абонентов): на нём весь подбор, 5-кратной **стратифицированной** кросс-валидацией (классы несбалансированы, 37% ушедших).

Разбиение то же, что в ПР-8: стратификация по `churn`, `random_state=42`.

## Что сделал

- Собрал пайплайн: one-hot для `region` и `tariff`, `StandardScaler` для числовых признаков, `XGBClassifier`. Вся предобработка внутри пайплайна, поэтому в каждом фолде она обучается заново и утечки нет.
- Оценил модель до подбора (параметры из шаблона ПР-8): ROC-AUC по пяти фолдам от 0,737 до 0,788.
- Провёл `GridSearchCV` по 96 комбинациям (`max_depth`, `learning_rate`, `n_estimators`, `min_child_weight`) и построил тепловую карту.
- Сравнил с `RandomizedSearchCV` при бюджете 24 и 96 комбинаций (непрерывные распределения параметров).
- Оценил лучшую модель на отложенном test и повторил кросс-валидацию тех же параметров на 10 новых разбиениях на фолды.
- Сравнил три оценки (лучший результат поиска, кросс-валидацию на новых фолдах, test) и показал разброс оценки по одному разбиению на 20 разбиениях.

## Результат

| Модель | ROC-AUC CV | ROC-AUC test |
| --- | --- | --- |
| XGBoost до подбора (300 деревьев, `learning_rate=0.05`, `max_depth=4`) | 0,760 | 0,779 |
| XGBoost после GridSearchCV (300 деревьев, `learning_rate=0.03`, `max_depth=2`) | 0,775 | 0,795 |

Подбор дал около +0,015. Главное изменение: деревья глубиной 2 вместо 4, то есть модель проще и меньше переобучается. `learning_rate` и `n_estimators` компенсируют друг друга (0,01 × 600, 0,03 × 300 и 0,1 × 100 дают почти одинаково).

| Метод поиска | Комбинаций | Время | Лучший ROC-AUC CV |
| --- | --- | --- | --- |
| GridSearchCV | 96 | около 5,5 с | 0,7754 |
| RandomizedSearchCV | 24 | около 1,3 с | 0,7693 |
| RandomizedSearchCV | 96 | около 4,5 с | 0,7758 |

При одинаковом бюджете случайный поиск нашёл не хуже сетки и немного быстрее; с четвертью бюджета он в 4 раза быстрее при проигрыше 0,006, меньше разброса между фолдами.

| Величина | ROC-AUC |
| --- | --- |
| Лучший результат поиска (`best_score_`) | 0,7754 |
| CV тех же параметров на новых фолдах (среднее по 10 разбиениям) | 0,7703 |
| Отложенный test | 0,7945 |

- `best_score_` завышен: это максимум из 96 шумных оценок, на новых фолдах те же параметры дают на 0,005 меньше.
- Test выше обеих оценок, потому что одно разбиение сильно шумит: на 20 разных разбиениях 80/20 ROC-AUC тех же параметров был от 0,743 до 0,794. Нашему test просто «повезло», честная оценка качества 0,77 ± 0,015.
- Test ценен не точным числом, а тем, что в подборе не участвовал.

Даже после подбора XGBoost (0,795) не лучше логистической регрессии из ПР-8 (0,806 на том же test).

Время поиска в notebook немного меняется от запуска к запуску, остальные числа воспроизводятся точно.
