# Матрица ошибок: вариант 13

ФИО: Эркинбеков Айман

**Основной уровень, пункты 1–6.**

Сценарий: анализ рентген-снимков. Положительный класс («да») означает, что на снимке есть пневмония. Все метрики округлены до трёх знаков без промежуточного округления.

## 1. Исходная матрица

Строки - факт, столбцы - прогноз модели.

| Факт / прогноз | Пневмония есть | Пневмонии нет |
| --- | ---: | ---: |
| Пневмония есть | TP = 58 | FN = 8 |
| Пневмонии нет | FP = 9 | TN = 225 |

Всего 300 снимков: 66 с пневмонией и 234 без неё.

## 2. Что означают ячейки

- **TP:** пневмония есть, модель её обнаружила (58 снимков).
- **FN:** пневмония есть, модель её пропустила (8 снимков).
- **FP:** пневмонии нет, но модель ответила «да» (9 снимков).
- **TN:** пневмонии нет, модель правильно ответила «нет» (225 снимков).

## 3. Метрики

**Accuracy** - доля правильных ответов:

$$\mathrm{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}=\frac{58+225}{300}=\frac{283}{300}\approx0{,}943.$$

Верны 94,3% ответов.

**Precision** - доля верных ответов «пневмония есть»:

$$\mathrm{Precision}=\frac{TP}{TP+FP}=\frac{58}{58+9}=\frac{58}{67}\approx0{,}866.$$

Среди таких ответов верны 86,6%.

**Recall** - доля найденных случаев пневмонии:

$$\mathrm{Recall}=\frac{TP}{TP+FN}=\frac{58}{58+8}=\frac{58}{66}\approx0{,}879.$$

Модель нашла 87,9% снимков с пневмонией.

**Specificity** - доля правильно распознанных снимков без пневмонии:

$$\mathrm{Specificity}=\frac{TN}{TN+FP}=\frac{225}{225+9}=\frac{225}{234}\approx0{,}962.$$

Правильно распознаны 96,2% таких снимков.

**F1** учитывает и precision, и recall:

$$F_1=\frac{2TP}{2TP+FP+FN}=\frac{2\cdot58}{2\cdot58+9+8}=\frac{116}{133}\approx0{,}872.$$

## 4. Если всегда отвечать «нет»

Такой вариант правильно определит только снимки без пневмонии:

$$\mathrm{Accuracy}_{\text{всегда «нет»}}=\frac{225+9}{300}=\frac{234}{300}=0{,}780.$$

Это ниже 0,943 у нашей модели, но он пропустит все 66 снимков с пневмонией. Поэтому одной accuracy здесь недостаточно.

## 5. Какая ошибка дороже

Для первичного отбора снимков дороже **FN**: пневмония есть, а модель её не отмечает. **FP** тоже создаёт лишние проверки, но здесь важнее не пропускать положительные случаи. Поэтому приоритетная метрика - **recall**; за precision тоже нужно следить.

## 6. Снижение порога

По условию 6 случаев переходят из FN в TP, а 28 - из TN в FP. Получаем TP = 64, FN = 2, FP = 37, TN = 197. Всего по-прежнему 300 снимков. Числовое значение порога в задании не дано.

| Факт / прогноз | Пневмония есть | Пневмонии нет |
| --- | ---: | ---: |
| Пневмония есть | TP = 64 | FN = 2 |
| Пневмонии нет | FP = 37 | TN = 197 |

Новые метрики:

$$\mathrm{Precision}=\frac{64}{64+37}=\frac{64}{101}\approx0{,}634.$$

$$\mathrm{Recall}=\frac{64}{64+2}=\frac{64}{66}\approx0{,}970.$$

$$F_1=\frac{2\cdot64}{2\cdot64+37+2}=\frac{128}{167}\approx0{,}766.$$

| Метрика | Исходный порог | Сниженный порог |
| --- | ---: | ---: |
| Precision | 0,866 | 0,634 |
| Recall | 0,879 | 0,970 |
| F1 | 0,872 | 0,766 |

**Вывод.** Для первичного отбора сниженный порог лучше по главному для нас показателю: пропущенных случаев стало 2 вместо 8, полнота (recall) выросла до 0,970. Но ложных тревог стало 37 вместо 9, а precision и F1 снизились. Значит, модель стала лучше для поиска возможных случаев, но не по всем метрикам сразу.
